# Slay the Spire

Second game plugin: turn-based, so the agent's thinking costs no game time, and every command is measurable. 
## How it works

- **Communication Mod** (ForgottenArbiter, 1.2.1, pinned in [UPSTREAM.json](UPSTREAM.json)) runs inside the game through ModTheSpire + BaseMod. It starts an external process, writes the full game state as one JSON line to that process after every change, and reads commands (`START`, `PLAY`, `END`, `CHOOSE`, `PROCEED`, `POTION`, `KEY`, `CLICK`, `WAIT`, `STATE`) from its stdout.
- **[bridge.mjs](bridge.mjs)** is that process (Windows Node, spawned by the mod). It answers the mod's `ready` handshake and exposes the same line protocol on `127.0.0.1:27183`, one client at a time; `{"aas":"screenshot"}` returns the game window as PNG (PowerShell, 960 px wide), `{"aas":"state"}` the latest state, `{"aas":"click","x":..,"y":..}` a real mouse click on the window. A new client is greeted first (the last state, or a hello), so a state already on its way is never taken for a command's answer.
- **[plugin.mjs](plugin.mjs)** is the game plugin: `sts` in `sts_exec` (`state()`, `play()`, `end()`, `choose()`, `proceed()`, `cancel()`, `potion()`, `key()`, `wait()`, `command()`, `screenshot()`; see [documentation.md](documentation.md)). Every command is a `game.playback`; its IGT is the game's own processing time (`seconds`), everything else is thinking. Milestones: every floor (no split), every act boss and the victory (`chapter: true`, splits `Act 1 boss`, `Act 2 boss`, `Act 3 boss`, `Heart`). The victory is also a `game.over` event: the harness ends the agent session, LiveSplit pauses (the milestone did the final split) and the run's status is `completed`. A death is a `game.over` without victory and a `Death N` milestone, not the end of the run: the controller refuses everything but `sts.restart()`, which leaves the death screen with the mod's `PROCEED` (its return button; a real click at `AAS_STS_DEATH_CONTINUE_XY` is the fallback) and STARTs a new run with the same seed, one playback. The new run is a new attempt (`game.attempt`): LiveSplit resets and splits for that run, the session RTA keeps running; `aas render --attempt last` cuts the last run out. A resume after a death STARTs with the seed from `run.jsonl` (the game deleted its save). `prepareRun` sends `START <class> <ascension> [seed]` (env `AAS_STS_CLASS`, `AAS_STS_ASCENSION`, `AAS_STS_SEED`), so the recording starts at Neow. The game's autosave is copied with every harness save (`<run>/saves/`), and `endRun` copies the run-history file the game writes when a run ends (`<run>/history/`). [save-track.mjs](save-track.mjs) `<run-dir>` decodes both (floor, act, path per floor, the game's own run clock, victory/defeat) and prints them next to the harness's IGT and splits from `run.jsonl`: the ground truth for the splits, as the demos are for Portal. Neither is published: the saves carry the player's profile name.
- **Windows side**: [install-mod.mjs](install-mod.mjs) puts `CommunicationMod.jar` and a copy of `BaseMod.jar` in `<game>/mods/`, the bridge in `AAS_STS_TOOLS_DIR` (default `<game>/aas/`), and writes `%LOCALAPPDATA%\ModTheSpire\CommunicationMod\config.properties` (`command=<node> <bridge> 27183`, `runAtGameStart=true`). [launch-game.mjs](launch-game.mjs) starts the bundled JRE with `ModTheSpire.jar --skip-launcher --skip-intro --mods basemod,CommunicationMod` (the loader's Workshop lookup needs Steam and is not relied upon), waits for the bridge. Optional and off by default, as for Portal: `AAS_STS_WINDOW_POS` moves the window `Modded Slay the Spire` (e.g. to a secondary display; sets the high-DPI override for the game's `java.exe` so the window keeps its pixel size across displays), `AAS_QUIET_AUDIO_DEVICE` routes the game's audio away from the speakers while it starts (`--process java.exe`), `AAS_KEEP_DISPLAYS_AWAKE=1` keeps the displays on. [stop-all.mjs](stop-all.mjs) closes the game window, ModTheSpire's log window (the JVM keeps it), LiveSplit (answers "Save Splits?" with No), OBS and Steam gracefully.
- Game settings changed by the harness: profile name `AAS` while the game runs (`AAS_STS_PLAYER_NAME`; the HUD shows it in every recording; the own name is restored by `stop-all` from `preferences/STSPlayer.aas-backup`), `Fast Mode` on (Communication Mod is only tested with it; backup in `preferences/STSGameplaySettings.aas-backup`), `info.displayconfig` windowed 1920x1080 when absent.

- **Scripted bot** ([bot.mjs](games/slay-the-spire/bot.mjs), runtime `scripted`): the winnability baseline and chain test on a fixed seed. Combat is decided by an oracle when `AAS_BOT_ORACLE` points at gamerpuppy's [sts_lightspeed](https://github.com/gamerpuppy/sts_lightspeed) test binary: at the start of every fight it loads the game's own autosave (written on entering the room), searches the whole fight RNG-accurately (`mcts_save`, 200k steps in about half a second) and the bot replays the best line, verifying every card against the live hand (any mismatch: the bot's own turn planner takes over). Outside combat: heuristics (map route, rewards, rests, shops, events). `AAS_BOT_TAPE` replays a run recorded with [tape.mjs](tape.mjs) before it decides for itself.
- **Goal**: the plugin declares the game's ends (`act1`, `act2`, `act3` = the game's own victory and the default, `heart`); `aas run --goal act1` makes the harness declare the victory when the act 1 boss falls, a short category for chain tests and first agent runs. `aas resume --goal act3` extends a won act1 run to the game's own end.
- **Seed**: the reference seed for the Ironclad act3 category is **23M** (`2577`), set as `AAS_STS_SEED=23M`; `aas run --seed <code>` overrides it per run. It was chosen on winnability measured with [seed-winrate.mjs](seed-winrate.mjs), which plays every candidate out as a whole run with the sts_lightspeed search agent; the criteria and the method are in [seed-criteria.md](seed-criteria.md). Act 1 has no elite on the route, a shop on floor 2 and a rest before the boss; the bosses are The Guardian, Automaton and Donu and Deca. Game version V2.3.4, Ironclad unlock level 5, ascension 0: the seed only reproduces at that combination. With no seed a run uses a random one, recorded in `summary.json`.

```bash
npm run sts:install                       # mod, bridge copy, mod config (once)
npm run sts:launch                        # game with mods, bridge on 27183
npm run sts:check -- --run-dir <dir> --exercise   # handshake, state, screenshot, exercise
npm run sts:run -- <runs>/sts-01 --headless --max-minutes 120   # Claude Code run (budget guard applies); closes game, LiveSplit, OBS and a Steam it started when the run ends (--keep-open leaves them)
npm run sts:stop                          # manual close of the same set (-- --steam closes Steam even when the launcher did not start it)
```

## Why Slay the Spire (and not Zero Company)

Offline, no anti-cheat, deterministic seeds, a bot API that already exists, runs of one to two hours, and speedrun categories to compare against. Kerbal Space Program (kRPC, Mun landing) is the next candidate.
